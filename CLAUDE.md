# CLAUDE.md

Descriptive, not prescriptive — present-tense facts about the tree, updated when the tree
moves; the only CLAUDE.md in the repo. Owner: the operator. Last reviewed 2026-11-12 (the event analog table; design docs local-only). Depth
lives in `DEVELOPMENT.md`, `Gravit-Design.md`, `face/README.md`, docstrings, and `docs/`.

## What this is
A market-strategy-account research workbench for one operator, one principal agent (Gravit) and
operator-authored bots, reset 2026-08-29 from the previous product. MARKET is the
market service in `market/` and ACCOUNT the wallet service in `account/` that Gravit reaches through its seat and the face shows on its
screens, with AKShare (A shares and more) as the market's sidecar; the repo holds no Python since 2026-10-24. STRATEGY is
`strategies/`, the agent's arena, run on DeepSeek Harness (dsh) inside `face/`, the chat face.

## Gotchas
- **The design documents live on the operator's machine alone** (since 2026-11-09): `Gravit-Design.md`,
  `DEVELOPMENT.md`, `ROADMAP.md`, `Gravit-Docs-and-Prompt-Loops.html` and `docs/superpowers/` are
  gitignored, so a worktree or a clone has none of them — read and edit them in the primary checkout
  (`git worktree list`'s first line), never `git add -f`. Commits before 2026-11-09 still hold them.
- **Nothing guards against lookahead and nothing backtests** (since 2026-10-24): the Account's
  history is read as it is, and a strategy's evidence is forward paper trading on its paper venue.
- **One order gate: Gate 2, the face's card on every Account-seat write** (`face/src/orders.ts`,
  only when dsh runs inside the face; `place_order`/`cancel_order` under any server are denied and
  refuse the boot). It is not containment — a shell turn can read the seat's key file and sign at
  the Account's door; the drill uses `mcp__drill__*` stand-ins (`face/README.md`). The owner's
  hand orders from Trade pass no gate of this tree's, only the Account's cap (charter D18).
- **`$DSH_HOME/profiles/face/cordis.yml` is rewritten to `[]` on every face boot.** The
  operator's file is `cordis.patch.yml`: the face's overlay rows (webserver, connection, the Remote
  controllers, the preset registry…) override it silently; `face/src/policy.ts` defaults yield to it.
- **The chat URL is tokenized.** Open the `…/?token=…` URL `npm start` prints: that visit sets a
  30-day cookie for the exact host:port (`localhost` is not `127.0.0.1`); `/api` 401s without it.
- **`face/client/*` is served with no cache headers** — hard-reload the browser after any client
  edit, or you drill a stale module.
- **The face, the Account and the market are three processes.** `cd account && npm ci` once;
  `npm run account` runs it on its default home `~/.buyer-agent-demo` (writes on — `--read-only`
  refuses paper orders too; it serves no page); `cd market && npm ci && npm run market` runs the
  market, which the face's Markets and its `mcp-market` row read. Paper venues only: let the seat
  in as **Gravit** on the face (Account › Agents) and sign it a `trade` limit naming a paper
  venue, never a real one. The three boxes (`docker
  compose up`, the face's 3090 the only port published) are the optional isolated run; the three
  host processes are the daily one.
- **The installed service holds 127.0.0.1:3090**, so the primary checkout's `face` preview cannot
  bind there: a second face needs another `FACE_PORT`, a scratch `DSH_HOME` and `FACE_DESK=0`;
  `npm run service` drives the operator's own launchd, so it is never run from an agent or a
  worktree.

Reading order for a new session: `Gravit-Design.md` §1–§2 → the `DEVELOPMENT.md` section you
are touching → `GRAVIT.md` for what Gravit itself sees.
