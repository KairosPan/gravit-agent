# market/ — the market service

gravit-market: the Market part's keyless public data as its own service on 127.0.0.1:4821 — the public sources and their stream hub, China (Tencent), Hong Kong, Korea, Taiwan and the world's cash indices (Regions, below), Ornn's compute indices (Compute, below), the AKShare sidecar, Lunhui's relay and iFinD, the face's Markets reads and gravit's `market_*` tools — with no wallet, no home and no key; it writes nothing to disk. It moved out of `account/` on 2026-11-03; origin and licence in `NOTICE` (which lists the files moved and copied) and `LICENSE` (Apache-2.0).
Install once: `npm ci` here (its own package and lockfile). The account's tests and typecheck import this package, so they need it too.

- Run: `npm run market` (127.0.0.1:4821, `--port <n>` elsewhere). It reads the repo's `../.env.ifind` when that file exists (`tsx --env-file-if-exists`), and its start lines say whether iFinD is configured (never the token) and which AKShare command it runs.
- As a LaunchAgent: `npm run market:service -- install` (`status`, `restart`, `logs`, `uninstall`), label `com.gravit.market`, logs in `~/Library/Logs/gravit-market/`. The operator installs it, never an agent. The plist passes `--env-file-if-exists=<repo>/.env.ifind`, so the token is read from that file at each start; the plist carries only the file's path. It keeps `PATH`, `HOME` and `MARKET_AKSHARE_BIN` from the installing shell.
- It serves no page: every path outside `/api/` is 404 with `MARKET_NO_PAGE`, and every answer is `cache-control: no-store`. The fence is the account's: a non-local `Host`, a foreign `Origin` or a `Sec-Fetch-Site` of `cross-site` or `same-site` is 403. `GET /api/health` is `{ok: true, service: "market", sources, china, akshare, ifind, wencai}` (`wencai`: iFinD configured and a budget above 0).
- What it answers (`src/server.ts` lists them): the source protocol the account reads it by (`src/protocol.ts`: `/api/sources`, `/api/source/:id/…`, `/api/hub…`, `/api/china/…`, `/api/price`); Lunhui's reach and AKShare (`src/routes-cn.ts`: `/api/cn/relay`, `/api/cn/ifind`, `/api/cn/wencai`, `/api/akshare/tools`, `/api/akshare/call`), which the Lunhui freezes, `market_wencai` and `market_akshare` ask directly — the account relays none of them; the public reads (`src/reads.ts`: `/api/explore`, `/api/quotes`, `/api/candles`, `/api/book`, `/api/trades`) and the stream (`src/follows.ts`: `GET /api/stream`, `POST /api/stream/markets`), which the face's Markets screens read through its market proxy under `/data/market`. A connected venue's own reads are the account's (`/api/account/connected/*`), never the market's.
- The face finds it at `FACE_MARKET_URL` (default `http://127.0.0.1:4821`): its `mcp-market` row (`face/src/market-row.ts`) and the proxy follow that row as composed, the Lunhui freezes read `FACE_MARKET_URL` alone, so an operator patch that moves the row moves the screens and the desk but not Lunhui.
- gravit's tools: `npm run market:mcp` (`src/mcp.ts`) is the market's own stdio MCP server, `market`, which the face spawns from this directory as its `mcp-market` row. Seven read-only tools, no key, no state, each a loopback fetch at `MARKET_URL` (default `http://127.0.0.1:4821`): `market_explore` (by `asset`, `form` and `region`, or the older `scope`/`tab`, never both; `source` takes one public source id or a comma-separated list), `market_quotes` (1–12 `venue|symbol` pairs; A shares by venue `china`, Hong Kong, Korean and Taiwanese shares by `hk`, `kr`, `tw`, a cash index by `ix` and `<region>:<id>`, an Ornn compute index by `ornn` and its id), `market_candles`, `market_book` (the book and the latest trades), `market_option_chain` (one option chain, below), `market_akshare` and `market_wencai` (问财, below). A market not answering is `isError` with `{ok: false, error}` and the market's one sentence. Gate 2 never cards them.
- iFinD: `IFIND_REFRESH_TOKEN` or `IFIND_ACCESS_TOKEN` in this process's environment (from `../.env.ifind`), held in memory and never in a reply, log line or refusal. Two routes use it: `/api/cn/ifind`, Lunhui's one fixed query, and `/api/cn/wencai` (`src/live/cn-wencai.ts`), 问财: `{question, type?, limit?}` — one Chinese sentence of 1–300 characters, `type` `stock` (default) or `fund`, `limit` 1–200 rows (default 50) — answered `{ok: true, question, type, asOf, columns, rows, rowCount, returned, truncated, tables?, budget}` with `x-cn-wencai: upstream`, or refused `{ok: false, wencai: <word>, message, detail?}` with `x-cn-wencai: refused`. 问财 spends a rolling 24-hour budget, `MARKET_WENCAI_PER_DAY` (default 100 upstream calls, `0` turns the route off; in memory, so a restart resets it; set it in `../.env.ifind`), that Lunhui's route neither counts nor meets; an answer is kept a minute by question, type and limit, and a kept answer spends nothing.
- Test: `npm test` (vitest) and `npm run typecheck`.

Design: `docs/superpowers/specs/2026-11-03-account-split-and-identity-design.md`; the as-built reference is `DEVELOPMENT.md` §3.10.

## Regions

Hong Kong, Korea, Taiwan and the world's cash indices are reads of their own, like China's — never registered public sources (no `source=` names them) — each keyless, GET over https only, its hosts on an allowlist in its module (`src/live/local-http.ts`), every row view-only (`canTrade: false`) and priced in its own currency (`currency`, turnover in `turnoverLocal`), never in `all` or a dollar path. `src/core.ts` builds all four in `realMarketCore`; each is optional in `MarketCoreOptions` (absent: that region's reads refuse in one sentence).

| Region | Module, venue | Hosts | Reads |
|---|---|---|---|
| Hong Kong | `hongkong.ts`, `hk` (Tencent) | `qt.gtimg.cn`, `stock.gtimg.cn`, `web.ifzq.gtimg.cn`, `smartbox.gtimg.cn`; backup ranking Eastmoney `push2delay.eastmoney.com` | the main board's 200 busiest by turnover (movers: re-sorted by move), quotes, 1D minutes and daily bars, search |
| Korea | `korea.ts`, `kr` (Naver) | `polling.finance.naver.com`, `m.stock.naver.com`, `api.stock.naver.com`, `ac.stock.naver.com` | the 200 largest KOSPI shares by market value, re-sorted by today's turnover or move (Naver has no turnover ranking), quotes, daily bars, search |
| Taiwan | `taiwan.ts`, `tw` (TWSE) | `openapi.twse.com.tw`, `mis.twse.com.tw`, `www.twse.com.tw` | the 200 busiest TWSE shares at the last close (ETFs left out), priced live from MIS in session; quotes, daily bars up to a year, search |
| Indices | `world-indices.ts`, `ix` | Tencent, Naver, TWSE MIS, Eastmoney `push2delay`/`push2his` (each index names its own chain; Eastmoney is alone for KOSPI 200's level and for KOSPI's and KOSPI 200's histories, and KOSDAQ has no history source) | each region's cash indices (`WORLD_INDICES`, `ix:<region>:<id>`), levels in points, daily history |

- Routing (`src/reads.ts`): `/api/explore?region=hk|kr|tw` on Stocks Spot (asset and form left out, or `stocks`/`spot`) is that region's ranking, with `q` its search, the read in `local` (China's answer carries `local` beside `china` too); `asset=indices&form=spot&region=<r>` is that region's cash indices. A `source` beside either is refused, and `sort=closing`. Every other region and form (perps on hk, jp, kr, tw, in, cn; Stocks Spot on jp, in, eu) is the generic path. A search on All asks China, Hong Kong, Korea and Taiwan beside the public sources, each within 4 s; a late or refused one is in `missing`. `/api/quotes` takes `hk|00700` (`hk|700` too, answered at `00700`), `kr|005930`, `tw|2330`, `ix|jp:n225`, one read per venue; `/api/candles` takes `hk`, `kr`, `tw`, `ix` by `range` alone, as `china`.
- The keeps: a ranking 10 s in session (Taiwan's live-priced 200: 30 s), a minute for the 45 minutes after the session ends (Hong Kong's closing auction, a delayed source's last prints), then until the next session; quotes the same way with 5 s in session; minute charts 30 s; daily bars 10 min (Taiwan's past months for the process, asked 2 s apart and once each); searches a minute (128 kept); index levels and quotes 15 s in session, then as a ranking. One flight per key; a failure is never kept. A ranking that fails, or answers empty, is answered from the last good one for up to 10 min, flagged stale.
- The pause: a 403, a 429, a redirect (none is followed) or a recognised refusal page stops every ask of that host for 15 min (`politeHosts`); the core hands every local source one guard over Tencent's, Naver's and TWSE's hosts (`localHosts`), and Hong Kong's backup and the indices one Eastmoney client, so a host's pause holds for every source that asks it. A source gets one retry on a timeout or network error, never a loop (none for TWSE's month pages). A quote says "real time" only where its source declares delay zero, its own figure where it declares one ("Naver · 15 min delayed"), its name alone otherwise.
- Tests never reach these hosts: the parsers read `test/fixtures/regions/` (its `README.md` lists each URL and what it showed), the sources a fake http.

## Options

Option chains are view-only reads of their own, like the regions — never registered public sources, never in `all`, never in a dollar path or the dollar-volume cut, every `at` entry `canTrade: false`. `src/core.ts` builds both in `realMarketCore` over the same shared `localHosts` guard as the regions; each is optional in `MarketCoreOptions` (absent: its reads refuse in one sentence).

| Source | Module | Hosts | What is read |
|---|---|---|---|
| Crypto | `options-crypto.ts` (Deribit, OKX) | `www.deribit.com`, `www.okx.com` | Deribit's book summaries (BTC and ETH inverse, in the coin; the USDC book's linear options, in USDC); OKX's coin-margined families (`<C>-USD`): tickers, index, `opt-summary` (IV = `markVol` x 100), `open-interest` |
| US | `options-us.ts` (Nasdaq) | `api.nasdaq.com` | `option-chain` per ticker: the list's ten (SPY, QQQ, IWM, AAPL, NVDA, TSLA, MSFT, AMZN, META, GOOGL) by their nearest expiry, any other ticker's chain when asked |

- Routing (`src/reads.ts`): `/api/explore?form=option` lists one row an underlying (`opt:BTC`, `opt:AAPL`, kind `optionChain`): `asset=crypto` the crypto rows, `asset=stocks` (region `us` or none) the US rows, both with neither; any other asset or region, no rows. `q` matches the listed underlyings; `sort` is `volume` (summed, in dollars where the source gives it) or `movers` (the size of the underlying's day change); `closing` and a `source` beside it are refused. A source's partial read is a note under the list, a stale list `stale: true`, a refusal a `missing` venue. `/api/options?underlying=&venue=deribit|okx|nasdaq&expiry=YYYY-MM-DD` answers `{ok: true, value: OptionChain}`; a coin is never asked of Nasdaq nor a US share of a crypto venue.
- The figures: a crypto row is Deribit's alone where Deribit lists the coin (its contracts are one coin, OKX's a fraction), else OKX's volume with no OI or IV; its day change is the coin's own row's (Crypto Spot). A US row is its nearest expiry's alone; its price and day change are the US stocks line's (`PublicSource.line`, kept 20 s), and the row lists without them while that line refuses. Only the sources' own figures: no computed IV, no Greeks; Nasdaq's legs carry no IV.
- The keeps: a crypto chain 30 s; a Nasdaq chain page 60 s in a US session, until the next US open outside it; the US list's summaries one Nasdaq ask per 3 s at most, each kept 10 min in session, until the next open outside it; OKX's option families once a day. A failure is never kept; a failed list answers the last good one up to 10 min, flagged stale. A chain is read only while its page is open or gravit asks; the list never reads a whole chain.
- The pause: a 3xx, 403 or 429 from one of these hosts stops every ask of it for 15 min, the guard shared with the regions' (`localHosts`). Bybit and Binance are not read: both refuse this place.

## Compute

Ornn's compute price indices are a view-only read of their own, like the regions and the options — never a registered public source, never in `all`, never a dollar volume, every `at` entry `canTrade: false` (venue `ornn`, name "Ornn"). `src/core.ts` builds it in `realMarketCore` over the same shared `localHosts` guard; it is optional in `MarketCoreOptions` (absent: Compute's indices refuse in one sentence, and its events still answer).

| Source | Module | Hosts | What is read |
|---|---|---|---|
| Ornn | `ornn.ts` (`ORNN_INDICES`, 13 rows `cmp:<id>`, kind `computeIndex`) | `data.ornn.com`, `api.ornnai.com` | `public-index/daily-index/all` (seven GPUs' daily settles, $/GPU·hr), `public-index/otpi` (four labs' token prices, $/M tokens), `public-index/otpi/weight-class` (closed and open); each row's history (`public-index/gpu/<name>/index-history`, `otpi?lab=`, `otpi/weight-class?class=`, three months); a GPU's intraday value (`api.ornnai.com/api/gpu/<name>`) |

- Routing (`src/reads.ts`): `/api/explore?asset=compute&form=spot` is Ornn's rows, by `volume` (GPUs by price, then the token rows) or `movers`; `closing` and a `source` beside it are refused. `form=event` is the prediction-market questions on the indices: the market's own search for `q=Ornn` (`exploreAcross`, the q path a user's search takes) over the event sources (or the sources listed), keeping only the rows `classOf` calls compute ("Ornn … Index" in the question). No form is both, the spot rows first: a refused or unread Ornn is a `missing` venue and the events answer; a late or refused search (or venue) is `missing` and the spot rows answer. A region, or any other form, beside `asset=compute` is the generic path (no rows). `/api/quotes` takes `ornn|<id>` (`ornn|h100`, `ornn|tok-anthropic`): the latest settle, `local.prevClose` the previous settle, the 30-day range, a GPU's `current` (or null with a note). `/api/candles?venue=ornn&symbol=<id>&range=` answers the daily settles by `range` alone (1M the last 30; 3M and longer the three months there are, with a note; 1D and 5D refused). An unknown id is refused in the market's words, naming the 13.
- The keeps: the three latest asks an hour each (a failed ask answers its last good read, flagged stale, up to 10 min past that read's keep, and is not asked again for 10 min); a row's history until 24 h after its last point (at least an hour), read in the background one at a time for the list's change; a GPU's current value 5 min, read only by its quote (its page on screen). A quote waits at most 3 s for the row's history and the current value and 5 s in all (under the face's 7 s cut): one late or failed is null with a note and is not asked again for 10 min; the `q=Ornn` event search 10 min, asked only by Compute's Event or no form.
- Change is the latest settle less the previous one, said so in the notes; nothing else is computed. Not read: Ornn's paid tiers (hourly prints, longer history, the API key) — the free tier is three months of daily settles.
- The pause: a 3xx, 403 or 429 from either host stops every ask of it for 15 min, the guard shared with the regions' and the options' (`localHosts`). Tests never reach these hosts: the parser reads `test/fixtures/ornn/` (its `README.md` lists each URL), the source a fake http, the reads a fake source (`test/fakes.ts` `fakeOrnn`).

## AKShare, the sidecar

The market runs `akshare-mcp` (a Python MCP server over AKShare, public A-share and other Chinese market data) as its own MCP child over stdio (`src/live/akshare.ts`). gravit reaches it through the market's own `market_akshare` (`{tool, arguments}`, `mcp__market__market_akshare`, a read: no card), which posts to `/api/akshare/call` here; the account relays nothing of it and the face runs no AKShare.

- Host install, once (needs `uv`; the Git source is intentional, because PyPI's normalized `akshare-mcp` is another project, and `mcp<2` stays because this revision uses the SDK 1.x FastMCP API):

  ```bash
  uv tool install --python 3.12 --with 'mcp<2' \
    'git+https://github.com/xiaozhozho/akshare-mcp.git@9b6a22b6d83cce2a996a5072743bb06686040ce0'
  ```

- The command is `MARKET_AKSHARE_BIN`, default `~/.local/bin/akshare-mcp` (argv only, no shell). The market image installs the same pin and sets it to `/usr/local/bin/akshare-mcp`.
- The child starts on the first ask, not at boot, and starts again on the next ask after it exits. One 120 s deadline covers a cold start, the tool listing and the call; a call that times out recycles the child. A reply past 4 MiB is refused `too-large`, arguments past 16 KiB `bad-arguments`; the child returns at most 500 rows (`AKSHARE_MCP_MAX_ROWS`), and a result says `truncated` when it cut.
- The child's environment is an allowlist of the market's own (`PATH`, `HOME`, `USER`, `LANG`/`LC_*`, the temp dirs, the TLS roots, proxies without their userinfo, `FASTMCP_LOG_LEVEL`): no iFinD secret reaches Python. Its stderr is this process's.
- Two routes, both reads: `GET /api/akshare/tools` lists the child's tools, `POST /api/akshare/call` takes `{tool, arguments}`. A refusal is `{ok: false, akshare: <word>, message}` with `off`, `unknown-tool`, `bad-arguments` (400), `unavailable` (503), `timeout` (504) or `too-large` (502).
- Live check: `curl -s 127.0.0.1:4821/api/akshare/tools` lists 14 tools.

## In the box

`docker compose up` at the repo root runs this service as the `market` box (`compose.yml`, `Dockerfile` here: AKShare's install layer, then `npm ci`; `.dockerignore` keeps the host's `node_modules` out). It runs `npm run market` with `MARKET_BIND=0.0.0.0` and `MARKET_HOSTS=market:4821`, publishes no port (`expose: ["4821"]`), has no volume, and reads `.env.ifind` through compose's optional `env_file`. The account box and the agent box read it at `http://market:4821` (the agent box for the Markets screens and its `mcp-market` row, `FACE_MARKET_URL`) and start once the market's health check (`GET /api/health`) passes; the agent box mounts this directory read-only, its `node_modules` a Linux volume, so `npm ci` here on the host comes first. **`MARKET_BIND` and `MARKET_HOSTS` are for the box only**: never set `MARKET_BIND=0.0.0.0` on the host Mac, and the `Host` fence is the DNS-rebinding defence, not authentication.
