# account/ — the Account service

The Account (Linqi's buyer-agent-demo, its portfolio part) as this tree's own package; origin and licence in `NOTICE` and `LICENSE`.
Install once: `npm ci` here.

- Run: `npm run account` (127.0.0.1:4820; flags `--read-only`, `--live-cap <usd>`, `--port <n>`, `--fresh`); the home is the code's default `~/.buyer-agent-demo`. As a LaunchAgent: `npm run account:service -- install` (`status`, `restart`, `logs`, `code`, `uninstall`).
- The Account serves no page (since 2026-11-01): it answers its API under `/api/`, and every other request is 404 with `NO_PAGE` (`src/portfolio/server.ts`: "The Account serves no page: its owner's screens are Gravit's face (Markets, Trade, Account). …"). Its owner's screens are Gravit's face (`../face/`, 127.0.0.1:3090), which reaches it through its proxy (`/data/account…`); a cross-site navigation is refused like any cross-site request, and `POST /api/account/signin/start` without the face's origin header is refused.
- The first owner: an Account with no owner prints a pairing code on its start line (`pairing code: …`; under the LaunchAgent `npm run account:service -- code`), typed on the face (Account, "Pair with the code the Account printed in its terminal"). Once it has an owner, a new device is let in only by a device that signs (the face's Settings › Devices): keep a second face browser paired.
- Who signs: `npm run account:owners` (`--url <origin>` for another Account) reads `GET /api/account`'s signers once and says `ownerless`, `face-signs` (a device labelled `Gravit face` is an owner — a hint, not a proof: check the face's device line) or `stop` (exit 3: in order, let the face in from a face browser that already signs, under Settings › Devices; with none, run the retired page from `9614314c` on the same home and let the face in or sign its device out there; `--fresh` last — it loses the owner, the venues, the agents and their limits); it prints each owner as `kind · label` and the count of devices waiting, never a key.
- The seat: `npm run portfolio:mcp` — the MCP seat the face's `mcp-account` row spawns. Its writes stop for the face's Gate 2 card, then, in Guard, for the Account's card, answered on the face under Account › Cards.
- The market: the Account reads the market service (`../market/`, 127.0.0.1:4821, `DEVELOPMENT.md` §3.10) through one link (`src/portfolio/market/`; `PORTFOLIO_MARKET_URL`, default `http://127.0.0.1:4821`), so start it too: `cd ../market && npm ci && npm run market`. The start line says `market: <url> · answering` or `not answering yet`; an Account started first fills in its sources once the market answers, with no restart. While the market is down, holdings keep their last price and carry `marketOld` with the one sentence `MARKET_DOWN` ("The market service is not answering, so prices here are not current."), a prepare refuses in those words, a paper order waits (it never fills on a price older than the market's last answer), and no net-worth point is taken.
- Markets: beside the venues' public markets the Account serves China, the A shares as Tencent ranks, quotes, charts and finds them (`explore?tab=china`, `quotes?pairs=china|<code>`, `candles?venue=china`, the seat's `china` tab), all read from the market (`../market/src/live/china.ts`). Keyless, view-only (`canTrade: false`) and priced in CNY, in the China tab alone and never in `all`. Only the real server builds the link, so tests and other services reach no market unless one is handed in.
- Lunhui's reach: `GET /api/cn/relay?url=` (the Lunhui freezes' Tencent and Eastmoney GETs) and `POST /api/cn/ifind` (the boards stand-in's 问财 query) are relayed to the market byte for byte — its status, its bytes and five of its headers (`RELAYED_HEADERS`) unchanged; the market holds the allow-list and the iFinD token (`../.env.ifind`, read by the market's start). When the market does not answer, the relay is 502 `{ok: false, relay: "unreachable"}` (iFinD: `ifind: "unreachable"`). Both are reads, behind the `Host` fence, and work with `--read-only`.
- Tests: `npm test` (vitest, one file at a time), green but for one clock-dependent case that can fail on the real clock (`test/unit/ui-standin.test.ts`, "prices move every few seconds…"); `npm run typecheck`. Both need `cd ../market && npm ci` first: the account's tests import `../market/src` and `../market/test` (running the Account itself does not: `src/` imports nothing of the market's). `test/standin/ui-standin.ts` is the face smokes' stand-in (the Account over simulated venues: no network, no money), on an ephemeral port by default and never on 4820 or 4821.

Design: `docs/superpowers/specs/2026-10-27-account-in-repo-design.md`, and for the page retired and A shares here `docs/superpowers/specs/2026-11-01-account-two-parts-design.md`, and for the market's move out `docs/superpowers/specs/2026-11-03-account-split-and-identity-design.md`. The face's side: `face/README.md` "The Account seat", "Markets and Account", "The Account in the face"; the owed live runs: "The two-parts drills".

## AKShare

The market runs the AKShare sidecar (`akshare-mcp`, `MARKET_AKSHARE_BIN`; install and limits in `../market/README.md`). The Account relays `GET /api/akshare/tools` and `POST /api/akshare/call` to it byte for byte, and Gravit reaches them through the seat's one read tool, `portfolio_akshare` (`{tool, arguments}`); when the market does not answer they are 503 `{ok: false, akshare: "unavailable", message: MARKET_DOWN}`. Live check: `curl -s 127.0.0.1:4820/api/akshare/tools` lists 14 tools while the market runs.

## In the box

`docker compose up` at the repo root runs this service as the `account` box (`compose.yml`, `Dockerfile` here: the image copies `account/` and runs `npm ci` at build) beside the face's `agent` box and the `market` box (`../market/README.md` "In the box"). The box publishes no port: only the agent box reaches it, at `account:4820` on the compose network. Stopping the host service is advised (one Account in sight), not required. Run `npm ci` here on the host before the first `docker compose up` (the dev loop needs it anyway): the agent box's `account-modules` volume mounts at `account/node_modules` inside a read-only bind of this directory, so the mount point must already exist.

- The box reads the market at `PORTFOLIO_MARKET_URL=http://market:4821` and starts once the market box's health check passes. It holds no iFinD token and runs no data sidecar: both are the market box's.
- The home is the volume `account-home`, mounted at `/data` (`npm run account -- --home /data`); it starts empty. The first owner pairs with the code the box prints (`docker compose logs account`), typed on the face (Account, "Pair with the code the Account printed in its terminal").
- A key-file venue reads a path on the service's own filesystem, so the file goes into the volume first — `docker compose cp <file> account:/data/<name>` — and the venue is named by that path, `/data/<name>`.
- Optional, before the first start: carry the host's home (its book, devices and seats) into the box — `docker compose create account` (the container, not started; `cp` needs one), then `docker compose cp ~/.buyer-agent-demo/. account:/data`, then `docker compose up`. Otherwise the paper venue is opened again in the box.
- The box sets `PORTFOLIO_BIND=0.0.0.0` (listen on the container's interface) and `PORTFOLIO_HOSTS=account:4820` (one more `Host` admitted beside loopback, for the agent box on the compose network). **They are for the box only.** The `Host` fence is the DNS-rebinding defence, not authentication: writes are authorised by the owner's signed envelope and the seat's key at the door, but a peer that reaches the port can forge `Host` for every read. Never set `PORTFOLIO_BIND=0.0.0.0` on the host Mac — it would serve the LAN. `PORTFOLIO_HOSTS` entries (comma-separated) are matched exactly and case-sensitively, lowercase as compose sends them. Under an admitted extra host the Account's host-derived URLs (the wallet challenge, a venue's sign-in start) are built on `account:4820`; only a compose peer sends that host, never the owner's browser, which reaches the Account only through the face (`/data/account…`) and so never sends `account:4820`.
