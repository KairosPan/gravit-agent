## 1. Intent

The face hosts DeepSeek Harness in-process and has run `0.2.0-rc.2` since 2026-10-01. Upstream has since
shipped the `0.2.1` line (five alphas, five release candidates) and the always-on desk (PR #9), the
heaviest consumer of dsh's agent plane, is about to lean on seams — `freezeMessage` with a caller id,
`sessionPersistence.flush()`, the durable inbox — that should be verified on the version the face will
run next, not the one it is leaving. This upgrade moves `face/` to the newest published release, adapts
every seam that moved, keeps the product's posture and behaviour where upstream changed a default, and
leaves the operator a go-live runbook for the live `~/.dsh`.

Why now, in the operator's words: the desk stacks on dsh and is not merged yet, so the bump lands under
it rather than after it; the Super-agent prototype (DeepSeek, 2026-10-31) declares `engines.dsh
^0.2.1-alpha.2`, a known-working combination the desk's next round reads from.

## 3. Goals, non-goals, anti-goals

**Goals.** `face/package.json` and its lockfile on the target; `npm test`, `npm run typecheck` and
`FACE_SMOKE=1 npm test` green in `face/`; every seam of §9 recorded as unchanged or adapted; the docs that
name the version following the code; a go-live runbook beside the 0.2.0 one; a report of what broke, how
it was fixed, which old sessions stay unreadable, and which new dsh features the desk could use later.

**Non-goals.** No new feature of dsh is adopted (no native schedule, no session state records, no
`outputSchema`, no external subagent backends, no `allowedAgentPresets` menus): §13 lists them for later.
No change to the desk's design. No merge into main, no push, no PR without the operator's word. The live
`~/.dsh` and the face on 3090 are never touched; the runbook is the operator's.

**Anti-goals** (what would make this a failure even if green). A boot that composes a different tree
while typechecking clean (the mirror drifting); a posture that quietly follows upstream where the
operator decided otherwise at 0.2.0 (telemetry, egress, the tool roster); a product behaviour that
changes without a named decision — in particular Gravit's research run turning from "call a role, read
its report" into something else because dsh's delegation tool did (§8 D20); a smoke suite that passes
for the wrong reason (§5, the `/tmp` lesson).

## 4. Constraints

- Work only on this branch and worktree; commit messages written to a file and `git commit -F`; English
  in docs, code and commits; Chinese in chat.
- `face/src/{desk-conversation,desk-session,telegram,watch,watch-eval,desk}.ts`, `face/scripts/service.ts`
  and their tests are being changed on `feat/desk-p1-p4` by the session "Superagent-Always-on"
  (an annotation lane, replay of undelivered alerts, idempotent Telegram delivery, a watchdog). This
  upgrade touches those files only where the version forces it, in commits of their own, and merges
  `feat/desk-p1-p4`'s tip before it is called done; if that session is still mid-change, it stops there
  and says so. As of the probe, none of those files needs a change for rc.5 (§7, §9).
- `CLAUDE.md` stays one short descriptive file; `DEVELOPMENT.md` and `face/README.md` carry the depth.
- `caffeinate -i` around every long run; the Mac idle-sleeps.
- The suite is run from a checkout **outside** `/tmp` and `$TMPDIR` (§5).

## 5. Method and evidence

1. **Baseline** on this branch at 0.2.0-rc.2: `npm ci`; `tsc` clean; `npm test` 2,868 tests, 2,838 pass,
   0 fail, 30 skipped. (A first run with `FACE_ACCOUNT_URL=http://127.0.0.1:9` in the environment failed
   eleven Lunhui `freeze:` tests: they reach the Account stand-in through that variable. The variable is
   for a scratch *face*, never for `npm test`.)
2. **Target install** of the whole dependency set in a scratch directory, and a `tsc` of a copy of the
   sources against it: one source error (`src/roles.ts`: `backgroundMode` is not in `dsh-tool-subagent`'s
   `Config`) and eight test errors (`webServer.port` is `number | undefined`).
3. **Probe worktree**: a detached worktree of this branch with every pin bumped. `npm install` in place
   fails `ERESOLVE` against the old lockfile (the installed `dsh-agent@0.2.0-rc.2` peers conflict); after
   deleting `package-lock.json` and `node_modules` a fresh install resolves clean (421 packages). Offline
   suite: 6 fail (the three pin assertions, two policy tests on the vanished `tool-ralph` row, the boot
   test's patch count). `FACE_SMOKE=1`: 32 fail, every real boot refusing on one cause — `default agent
   preset "gravit" is broken: role-<id> (@deepseek-ai/dsh-tool-subagent): tool-subagent: persona is no
   longer supported; configure persona and tool plugins in an Agent Preset and select it with agentPreset
   (spawn only)`.
4. **Two throwaway spikes in the probe** peeled the next layers: roles composed as presets (one
   `dsh-agent-preset` row per role over `plugins/bot.js`, the tool row with `agentPreset`) — 28 fail; then
   `{{cwd}}` dropped from the persona — 25 fail, of which the pin/policy/mirror/shape tests were expected,
   five were the probe's own location (next item), and the rest are §7's breaks B2, B4, B9, B10.
5. **The `/tmp` lesson.** Five smokes (desk, schedule, watch, room, telegram) failed in the probe on
   writes the sandbox should have fenced. dsh's `workspace-write` grants the session cwd **and** `/tmp`
   and `os.tmpdir()`, canonicalized (`/tmp` is `/private/tmp` on macOS; `dsh-sandbox` `writableRoots`,
   unchanged byte for byte between the versions), and the probe worktree lived under `/private/tmp`. The
   same five fail at 0.2.0-rc.2 from a copy of the unchanged tree under `/private/tmp`, and pass at rc.5
   with their fixture roots moved outside the temp roots. Not an upgrade break; a precondition the plan
   makes loud (§7 B12).
6. **Four seam reads** over the two installed trees and the two source tags, one per plane (agent plane;
   subagents and presets; host, wire and boot; sandbox and guards), each a table of seam → OLD fact → NEW
   fact → verdict, folded into §7 and §9.

## 7. The breaks and the fix for each

Each break: what fails, why, the fix, and what proves it. Ids are this document's (`B<n>`); decisions
they rest on are §8's (`D<n>`, continuing the 0.2.0 re-host's D1–D18).

**B1 — the role library's tool rows no longer load.** `src/roles.ts` renders one `dsh-tool-subagent` row
per role with `persona`, `toolFilter` and `backgroundMode`; the first two fail at load, every preset that
carries them lists `broken`, and `bootFace` refuses a broken default (every real boot). *Fix (D20):* each
role becomes an agent preset of its own, `role-<id>`, composing two rows — the face's `gravit.js` with
`{}` (the date section alone, which a role child otherwise loses: its scope chain is [child, role
preset], never Gravit's preset) and `plugins/bot.js` with `{ persona, allow }` (the persona at
`deployment:persona-prefix`, the mask by `tools.restrict`, re-expanded on `tools/change`; `bot.js` is
reused unchanged, its header gaining a sentence). The presets are declared **after boot**, exactly as the
bots and `gravit-desk` are (the registry activates a declaration eagerly, and `bot.js` throws at mount
when none of a role's names is registered yet — a static overlay row would race the rows that register
`skill`, the `lunhui_*` tools and any MCP tool; after `boot()` every host tool exists and a late MCP tool
enters on re-expansion). Nothing needs them earlier: the `role_<id>` tool is the face's own (B2) and
resolves its preset at the call, so a call in the mid-boot window fails `agent-preset/not-found` with no
child, and nothing silently. `bootFace` refuses the boot when a role preset is missing or listed broken,
as it refuses a broken `gravit-desk` (and as 0.2.0 did, where a bad role row broke the default preset):
the face has no role library without them. `src/bots.ts` reserves the `role-` prefix (a duplicate
preset id throws at the registry). The mirror `bots/gravit/agent.cordis.yml` is regenerated. `header.agentPreset` of a role child is now `role-<id>`
(was `gravit`): Lunhui's `callerIsRole` additionally requires that prefix, which closes residual R44 (a
plain `subagent` child of Gravit could submit a module). *Proof:* `roles.test.ts` (the preset definitions,
the row shapes, the mirror), `bots.test.ts`, `overlay.test.ts`, `boot.test.ts`; the roles smokes
(persona, exact tools, the date, the header, the result).

**B2 — a role call no longer returns the report.** dsh's tool starts a managed activation and returns at
once; the report arrives later as a `subagent-settled` notice (a `user/message` whose `source.kind` is
`subagent-settled`), by `steer` into a running parent or `followup` into an idle one — and is dropped
if the parent is not live. dsh's shared guidance paragraph now names every delegation tool, role tools
included, and tells the model to start them together; the goal-round driver waits for running children
before the next round. The research cycle, the Lunhui run and module protocols, `gravit:roles`, the
client's Children view and five smokes all assume one call, one report. *Fix (D20):* the face owns the
role tool. `face/plugins/role.mjs` (a plain `.mjs` row like the Lunhui rows, importing `defineTool` from
`@deepseek-ai/dsh-tools`) is composed once per role inside Gravit's preset in place of the
`dsh-tool-subagent` row, with config `{ tool, name, summary, agentPreset, allow, model? }`. It registers
the tool into the calling context (the preset's standing layer, so Gravit and a fork child see it and a
role child does not, exactly as today). `execute` keeps the two checks 0.2.0 made at each delegation and
the service no longer makes: every `allow` name must resolve in the tree (`ctx.tools.get(name)`), or the
call is refused naming the missing tools with no child created — the rc.2 contract of `roles.ts`'s
header, the template's README and the roles smoke, kept because `bot.js`'s mask would otherwise let a
child run quietly short of a tool; and a `model` route is preflighted the way `room.ts` validates a
bot's (`llm.resolveCallConfig`), since `dsh-subagent` itself never preflights a route (only dsh's own
tool does). Then it calls `ctx.subagents.startActivation({ provider: "spawn", label, request: { prompt,
parent: exec.agent, agentPreset, agentOptions?, maxDepth }, signal: exec.signal, delivery: "caller" })`,
awaits `activation.result`, maps a non-`completed` `stopReason` (`aborted`, `error`, `max-tokens`,
`refusal`) to an error result carrying the reason and the provider diagnostic, returns the child's output
text otherwise, and disposes the activation in every path — on `exec.signal` too, since the caller owns
cancellation after publication. `isConcurrencySafe: () => false`, so two role calls in one step run one
after the other, which closes the 2026-10-28 drill's finding (reviewer alongside mode) at the tool; no
`timeoutMs` (the cooperative timeout policy is opt-in per tool, as at 0.2.0 for the subagent tool).
`maxDepth` comes from `ctx.subagents.resolveMaxDepth(undefined)` as dsh's tool does; the service enforces
the depth cap, the preset's existence (`agent-preset/not-found` / `invalid`) and the `maxActiveSubagents`
limit. What stays as it is: every contract (`cycle.md`, `lunhui-run.md`, `lunhui-module.md`),
`gravit:roles`, the client, the Lunhui smokes' flow. What changes in prose: `persona.md`'s delegation
paragraph (D27), `ROLES_INTRO` (a role child is now listed by `list_agents` and must never be sent a
`send_message`: a follow-up resumes it and its submits answer `ALREADY_SUBMITTED`),
`roles/_template/README.md`, the role drill. *Proof:* `roles-smoke` (the report in the tool result; a stop reason as an error; Stop on Gravit
aborting the child; a fork child's system text still equal to Gravit's), the Lunhui run smokes unchanged
in flow, `gravit-plugin.test.ts`.

**B3 — every model request fails on `{{cwd}}`.** `dsh/profile/persona.md` says "Your working directory is
{{cwd}}"; the loop no longer registers that variable (`unknown prompt variable "{{cwd}}" in section
"deployment:persona-prefix"; registered variables: provider, model`), so the desk, the schedule, the
watch, the rooms and the goal loop all die at the first request. *Fix:* the sentence goes; the
`working-directory` runtime context (order 100) now tells the model its directory, and follows a `cd`
where the persona's fixed value could not. `src/persona.ts` `PERSONA_VARIABLES` becomes `["provider", "model"]` (what the rc.5 loop registers) and
the strict template stays strict. *Proof:* `persona.test.ts` (the renderer's registered variables),
`bots-smoke` (the prompt renders), `instructions-smoke`.

**B4 — the `tool-ralph` row is gone from dsh-base** (policy D9 half one patches a row that no longer
exists; `policy.test.ts`, `boot.test.ts`, `smoke.test.ts`'s roster). The package is still published,
standalone, peering exactly what dsh-base mounts (`dsh-agent`, `-llm`, `-subagent`, `-system-prompt`,
`-tools`, `-workflow`; it injects `workflowEngine`, which dsh-base's `workflow-ptc` row provides). *Fix
(D9, re-taken):* keep ralph, as the operator decided at 0.2.0 — declare `@deepseek-ai/dsh-tool-ralph`
exactly in `package.json` and move D9's first half from an id patch to a `POLICY_INSERTS` row with the
config dsh-base used to carry (`subagentProvider: spawn`, `maxRounds: 64`; the standalone default is
256). `PolicyInsert` gains an optional `config`. An operator row `disabled: true` on `tool-ralph` still
turns it off. *Proof:* `policy.test.ts` (eight id patches, two inserts), `smoke.test.ts` (`ralph`
registered). Settled in the probe: with the package declared and the insert in place, the boot smoke
passes and `ralph` is in the roster.

**B5 — `webServer.port` is `number | undefined`.** Eight test sites pass it as a number; the face's own
uses (`main.ts`, `boot.ts`) read it after listen. *Fix:* the tests read the port through one helper that
asserts it is bound; `overlay.ts`'s comment on the `host` literal is corrected (the schema admits any
concrete address now; `FACE_BIND` keeps its contract, and a wildcard is refused at load by dsh itself).
*Proof:* `tsc`.

**B6 — the instructions chain: a racy smoke and a second global root.** `instructions-smoke` failed once
in the probe's full run on its own positive assertion (`baseline.length > 0`: no `agent-instructions`
baseline in the session) and passes alone, with the baseline present and `GRAVIT.md` the only file in
it. The face's candidate lists still apply; the smoke's wait does not: it prompts over the Remote with
`mode: "queue"` and then awaits `agent.whenIdle()`, which at rc.5 can resolve before the queued prompt
is claimed (the agent-plane read on `followup` and the inbox is the reference). *Fix:* the smoke waits for
the session's `turn/end` (the other smokes already do) — and every smoke that pairs a Remote prompt with
`whenIdle()` gets the same treatment where the plan finds one. Separately, rc.5 reads a second
user-global instruction file, `<agentsHome>/AGENTS.md` (`~/.agents` unless `DSH_AGENTS_HOME`), with no
row switch; neither global file exists on the operator's machine today, so Gravit's chain is still
`GRAVIT.md` alone. *Fix (D25):* `bootFace` audits both global files at boot and prints one line on
stderr when either exists ("`<path>` would enter every agent's instruction chain; the face's contract
is GRAVIT.md alone"); no override of `DSH_AGENTS_HOME`, because `skill-filesystem` resolves its default
roots from the same variable. The runbook names the check. *Proof:* `instructions-smoke` (the wait; a
fixture `$DSH_HOME/AGENTS.md` reported by the audit line), `boot.test.ts`.

**B7 — closed: the gateway's new access control does not reach the face.** dsh-base mounts
`remote-access`; the face's browser peer, signed in by the browser-session cookie, is the owner, which
access control never checks; every Remote the client calls and the `$events` stream over the mux hold
(the probe's client-mux, boot and Gate-2 smokes pass at rc.5 once B1 is out of the way). No overlay row,
no config. The seam enters the ledger (§9) and the upgrade guide's watch list.

**B8 — `session/projections` returns a kinded envelope.** `{kind:'sequenced', asOfSeq, values}` for a
V4 log, `{kind:'migration-required', values}` without `asOfSeq` for an older one, or `null`. The
client's `live.js` (two sites) and `member-traces.js` require `asOfSeq`, so a pre-V4 session's page
fails to open where 0.2.0 showed the refused-session status line. *Fix:* the client's projection reader
takes the kind: `sequenced` as today, `migration-required` as the status line the face already shows for
a refused session, `null` as empty; `summaries.js` carries `formatStatus` through so the list can say
why. The fixture validator (`npm run check:fixture`) on the new tree prints `26 lines; 23 validated with
dsh 0.2.1-rc.5's acceptance code, 0 rejected; no upstream validator for: 2 assistant-stream, 1
projection` — the rc.2 baseline; the three new event types are not in the fixture and the mapper ignores
unknown types. *Proof:* `api.test.ts` / `mapper.test.ts` on a `migration-required` frame,
`member-traces.test.ts`, `summaries.test.ts`.

**B9 — the bots roster lists the role presets.** `agentPresets.list()` now returns `role-*`; `bots-smoke`
pins the roster. *Fix:* the roster readers filter `role-` ids as they filter `gravit-desk` (B1's
reservation). *Proof:* `bots-smoke`, `bot-presets.test.ts`.

## 8. Decisions

The 0.2.0 re-host's D1–D18 stand (`docs/dsh-upgrade-guide.md` §4 is the table). Re-taken or new:

- **D9 (re-taken): `ralph` stays, inserted.** See B4. The alternative, retiring it, is one commit if the
  standalone row cannot mount; nothing in the product calls it.
- **D19 (new): `tool-working-directory` disabled by the policy layer.** dsh-base now gives every agent
  `working_directory {cd}`, which moves a session's current directory (reads, writes, bash, the
  instruction chain follow it; the sandbox root does not). The face's channels are directories and its
  contracts say "whose cwd is the directory"; the desk's guard places relative paths against
  `header.cwd`. Keeping 0.2.0's roster is the policy layer's rule; the `working-directory` service and
  its runtime context stay (B3 relies on it). One operator row re-enables the tool. Pinned by
  `policy.test.ts` and the roster assertions.
- **D20 (new): roles are presets, and the role tool is the face's.** The two halves of B1/B2. The
  alternative — dsh's `dsh-tool-subagent` with `agentPreset`, the report arriving as a notice — was
  rejected for this upgrade: it changes Gravit's research run into a chain of turns driven by notices,
  loses a notice when the face is not live at settlement (no durable parent mailbox upstream), lets dsh's
  own guidance push Gravit to start roles in parallel, and forces the two Lunhui protocols to carry wait
  rules under byte caps already at their limit. The face-owned tool keeps the product's observable
  behaviour and the contracts, at the cost of ~150 lines the face owns (the activation call, the stop
  reason mapping, disposal on abort) over a seam upstream documents as the programmatic path. If a
  later dsh removes `delivery: 'caller'`, this decision is re-taken.
- **D21 (new): the persona no longer names the cwd.** B3; the working-directory context does.
- **D22 (new): `web-deepseek-api` stays mounted, unselected.** It registers the `deepseek-search-api` and
  `deepseek-fetch-api` providers with the same credential and makes no request unless the `web` row
  selects them; D6's full restatements stand as written — dsh-base's `tool-web` is still
  `{ fetch: true, searchTimeoutMs: 60000 }` (schema keys unchanged) and `web` is still
  `{ searchProvider: deepseek-official, fetchProvider: http }`, both keys now `volatile` (settings-
  switchable, moot without a `settings` service), so the face's `{ fetch: false, searchTimeoutMs: 60000 }`
  and `{ searchProvider: deepseek-official }` drop no new key. `spill-policy` (D18, 12500),
  `agent-default-model` and `skill-filesystem` are unchanged. No new egress, so no policy row.
- **D23 (new): `remote-access` is dsh-base's row, not the overlay's.** B7: the browser is the owner.
- **D24 (new): the fixture roots stay inside the repository, and the precondition is loud.** B12.
- **D25 (new): the second global instruction root is audited, not overridden.** B6. `DSH_AGENTS_HOME`
  also moves `skill-filesystem`'s default roots, so the face leaves it alone and says, at boot, when a
  global `AGENTS.md` would enter the chain.
- **D26 (new): the runbook treats the rollback as lossy.** §10: a session that ran one `bash` call under

## 13. New dsh features the desk could use later (report only; none built)

- **A native schedule.** `@deepseek-ai/dsh-schedule` + `dsh-tool-schedule` ("host-wide durable reminders
  with shared management and original-Session delivery"; `schedule_create/list/update/delete` over a
  Host `ctx.schedule` service): the meta package ships them, dsh-base does not mount them. The desk's
  standing orders (`schedule.ts`, `firing.ts`) are a market-calendar clock with a ledger, deadlines and
  a token budget; the native one is wall-clock reminders delivered to a session. dsh-base does not
  mount it; its injects are all in the face's tree. One trap before anyone mounts it: it delivers with
  message source kind `schedule`, the kind the desk already declares for its own firings
  (`src/desk-session.ts`, the client's `DESK_KINDS`) — one of the two must be renamed first.
- **Caller-delivery worker children.** `startActivation({ agentPreset, delivery: "caller" })` plus
  `await result` gives a producer or a firing a bounded worker with its own mask and route, without
  waking Gravit or a notice in a thread (the same seam D20 uses).
- **`outputSchema`** on spawn and fork: a validated `result.structured` — typed reports instead of
  prose, or a typed answer from a Lunhui module.
- **`allowedAgentPresets`**: one delegation tool whose `agent_preset` enum carries each preset's
  description — a model-chosen worker menu.
- **Plugin state records** (experimental, new at rc.5): ``appendPluginRecord(session, `plugin:<name>`,
  data)`` and `pluginRecordOf(event)`, ignorable log-only events the model never sees that survive fork
  and resume; older readers skip them, migrations keep them best-effort, re-entrant appends are refused
  (defer out of a `session/event` listener), and upstream gates the call to its own `experimental`
  packages — outside the repo it is merely unstable. A per-session delivery or idempotency mark for the
  desk, inside the session.
- **Dynamic context** (`systemPrompt.context({..., required?, interpolate?})` + `refreshContext`,
  re-evaluated on each request): the desk's state could be a scoped `required` context instead of an
  injected user message — still model-visible, one runtime-context message per changed snapshot.
- **`@deepseek-ai/dsh-time-context`** (not installed): a durable clock reading at each step — ISO time,
  zone, time since the last model-visible message; `refreshIntervalMs` (600 s default) — a complement to
