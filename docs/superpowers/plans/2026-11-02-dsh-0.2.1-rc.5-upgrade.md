# dsh 0.2.1-rc.5 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move `face/` from dsh 0.2.0-rc.2 to 0.2.1-rc.5 with every seam the face and the desk stand on adapted, the suites green, the docs following the code, and a go-live runbook for the operator.

**Architecture:** The pins move together under a fresh lockfile; the policy layer keeps the product's posture where dsh-base moved (ralph inserted, `working_directory` off); the persona stops naming the cwd; the role library becomes one agent preset per role (persona + mask through `plugins/bot.js`) called through a face-owned `role_<id>` tool that starts a caller-delivery activation and returns the report in the tool result, so the research contracts do not change; the client learns the kinded `session/projections` envelope; the docs and a runbook follow.

**Tech Stack:** Node 22, TypeScript (tsx, `node --test`, `node:assert/strict`), the dsh plugin family at 0.2.1-rc.5 (`@deepseek-ai/dsh-tools` `defineTool`, `@deepseek-ai/dsh-subagent` `startActivation`, `@deepseek-ai/dsh-agent-preset`), plain-JS/`.mjs` plugins under `face/plugins/`.

**Spec:** `docs/superpowers/specs/2026-11-02-dsh-0.2.1-rc.5-upgrade-design.md` (B<n> = its breaks, D<n> = its decisions).

## Global Constraints

- Every `@deepseek-ai/dsh-*` dependency is pinned **exactly** `0.2.1-rc.5`; `@deepseek-ai/cordis` `4.0.5`; `@deepseek-ai/cordis-plugin-include` `1.0.10`; `src/version.ts` carries the same three literals (`DSH_PIN`, `CORDIS_PIN`, `CORDIS_INCLUDE_PIN`).
- Commands run from `face/` unless a path says otherwise: `npm test` (offline), `npm run typecheck`, `FACE_SMOKE=1 npm test` (the real boots), one file with `npx tsx --test tests/<file>`; wrap long runs in `caffeinate -i`. Never set `FACE_ACCOUNT_URL` for `npm test`.
- The suite runs from a checkout **outside** `/tmp` and `$TMPDIR` (this worktree qualifies; the scratchpad probe does not).
- Commit messages are written to a file in the session scratchpad and committed with `git commit -F <file>`; no backticks in `-m`. English in code, comments, docs and commits. Match the surrounding comment density and voice (present-tense facts, decisions named by id).
- Do not touch `face/src/{desk-conversation,desk-session,telegram,watch,watch-eval,desk}.ts`, `face/scripts/service.ts` or `tests/{desk,telegram,watch,schedule}-smoke.test.ts`: another session edits them on the parent branch, and the spec found nothing in them the version forces.
- Never read or write the operator's live `~/.dsh`; every boot in a test uses its own `mkdtemp` home, as the existing smokes do.
- The product's observable behaviour is unchanged by design: a role call still returns the role's report (D20); `cycle.md`, `lunhui-run.md` and `lunhui-module.md` are not edited.

## Review Focus

1. **Stop while a role runs.** The operator presses Stop (`session/cancel`) during a `role_<id>` call: the activation is disposed, the child is interrupted, the tool returns an error result naming the stop, and no child session keeps running. → Task 3's smoke, the abort case.
2. **A role whose tools the tree lacks.** `role.yml` names a tool that is not registered (an MCP server down, a typo): the call is refused with the missing name and no child is created — never a child with fewer hands than its file says. → Task 3's smoke, the missing-tool case (the rc.2 assertion kept).
3. **A role preset that cannot mount.** Every `allow` name missing at boot makes `bot.js` throw at the preset's mount: the boot must refuse with the role's id and reason, not list a broken preset and fail at the first call. → Task 2's smoke case.
4. **A pre-V4 session in the list.** `session/projections` answers `{kind: 'migration-required'}` with no `asOfSeq`: the page shows the refused-session status line it shows today, the list still renders, nothing throws. → Task 5's client tests.
5. **A wildcard bind.** `FACE_BIND=0.0.0.0` (the old docker value) is refused by dsh at load: the boot fails loud with the webserver row's reason, and the entrypoint never produces it. → Task 6's test and entrypoint.
