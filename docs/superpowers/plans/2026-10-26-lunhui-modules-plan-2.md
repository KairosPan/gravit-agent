# Lunhui Modules, Plan 2: the market modules, the analyst role, the run protocol

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give a `cn-market` run its three market artifacts: the run seals on its first context
read, a shared contract core validates every module, three module rows (environment, sentiment,
theme) register their read/submit pairs, the role `cn-market-analyst` writes the artifacts, the
`lunhui:run` protocol section tells Gravit the order, and a stub-model real boot drives one whole
market run on fixtures end to end.

**Architecture:** The backbone service (`face/plugins/lunhui/runs-row.mjs`) gains the module
plumbing — seal-on-read, per-module call budgets, the context-read set, the submit path that
validates and writes `<module>.json` and appends to `run.json`'s `artifacts[]`, and a bounded
evidence reader. `lib/contract-core.mjs` holds the rules every module shares (lifted from stage 0's
`lib/contract.mjs`, which keeps its stage-0 parts and imports the core); `lib/contracts/<module>.mjs`
holds each module's schema, rules, hypotheses, hints and example. `lib/module-tool.mjs` builds a
module's two tools the way `lib/freeze-tool.mjs` builds a freeze. Each module is one row file. The
protocol file `dsh/profile/lunhui-run.md` reaches Gravit through a new `protocols` entry of the
`gravit` row, rendered as a scoped section exactly as `cycle` is.

**Tech Stack:** Node 22, dsh `0.2.0-rc.2` (`defineTool`, cordis `inject`/`provide`,
`ctx.systemPrompt.section`), TypeScript for `face/src`, ES modules for `face/plugins/`, `node --test`
through tsx; real boots with `FACE_SMOKE=1` and `tests/stub-llm.ts`.

**Spec:** `docs/superpowers/specs/2026-10-25-lunhui-modules-design.md` (approved 2026-10-25), §10
item 2, with §12's build notes from plan 1. Plan 1's ledger,
`docs/superpowers/plans/2026-10-25-lunhui-modules-plan-1-ledger.md`, records the rulings this plan
builds on.

## Global Constraints

- dsh stays `0.2.0-rc.2`; no dsh package edited, forked or re-pinned; no new package in `face/package.json`.
- Tool names are plain: this plan adds exactly `lunhui_read_environment_context`, `lunhui_submit_environment`, `lunhui_read_sentiment_context`, `lunhui_submit_sentiment`, `lunhui_read_theme_context`, `lunhui_submit_theme` (spec §5.5).
- Row ids added: `lunhui-environment`, `lunhui-sentiment`, `lunhui-theme`, composed after the four freeze rows (spec §5.12).
- Tool descriptions, refusal texts, contexts, hints, hypotheses, `ROLE.md` and `lunhui-run.md` are Chinese; code, tests and docs English (D14′).
- Every refusal is a thrown `LunhuiError` opening with its code word, naming no path (§5.7). New codes this plan uses: `NOT_A_ROLE`, `READ_FIRST`, `ALREADY_SUBMITTED`, `WRONG_CHANNEL`, `TOOL_BUDGET`, and validation rejections as `[<category>] <reason>\n修复：<repair>` with code `INVALID_ANALYSIS`.
- Module budget: ten calls per module per run, reads and submits, refused ones counted, persisted in `metrics.json` `calls[<module>]`; past it `TOOL_BUDGET` with the stop instruction (A7).
- A submit refuses a root or seeded-fork caller with `NOT_A_ROLE` (the inverse of `callerIsChild`, A23); a read is open to any caller.
- The environment, sentiment and theme modules accept only a run of `cn-market` (`WRONG_CHANNEL`).
- A context is a digest ≤ 30 KiB of UTF-8 JSON text (A24), carrying a `truncated` list of what was left out.
- An artifact ≤ 24 KiB compact JSON (§5.6); one per module per run (`ALREADY_SUBMITTED`); written atomically, then named in `run.json` `artifacts[]` (A10, plan 1's §12 row).
- The artifact envelope (A19): `module`, `contract_version` (`"1"`), `hypotheses_version` (`"h_" + 12 hex of sha256 over the module's hypotheses text`), `snapshot_id`, `run`, `as_of`, `session`, `status` (`"OK"` or `"NOT_EVALUABLE"`), `missing_sources` (array, empty when OK), the module's headline fields, `claims`, `limitations`.
- Never edit `dsh/profile/cycle.md`, `dsh/profile/persona.md`, `bots/` (save the generated mirror `bots/gravit/agent.cordis.yml`, regenerated by `npm run render:roles`), the live `~/.dsh`, or the manuscript's git status. No manuscript text in the tree: hypotheses are the tree's own words with paragraph ids, taken from `strategies/cn-market/THESIS.md`.
- `GRAVIT.md` ≤ 4,500 bytes; `lunhui-run.md` ≤ 3,000 bytes; `ROLE.md` ≤ 2,000 bytes.
- Commit after every task, `git commit -m` without backticks, `$` or parentheses; plain one-line git commands from the worktree root; edit with the file tools; never push.
- Tests never reach the network or a real model; real boots are `FACE_SMOKE=1` with a temp `DSH_HOME`, port 0, the stub adapter.
- Commands: `cd face && npx tsx --test tests/<file>.test.ts`; `npm test && npm run typecheck`; `FACE_SMOKE=1 npx tsx --test tests/<smoke>.test.ts`.

## Review Focus

1. Two context reads of one open run arriving together must seal it once, both returning the same `snapshot_id` — Task 2.
2. A freeze arriving after a context read must refuse `RUN_SEALED`, never add evidence the reader did not see — Task 2.
3. A submit after a face restart without a new read must refuse `READ_FIRST`, while the module's call count survives the restart — Task 2.
4. An artifact citing an evidence id of another run, or a derived id of a source the module does not read, must be `[REFERENCE]` — Task 1 and Tasks 4–6.
5. A sentiment or theme sentence asserting a 情绪/题材 statement with no derived evidence id must be refused `[UNSUPPORTED_SCOPE]`, the same sentence citing one accepted — Tasks 1, 5, 6.

  - `SCOPE_CLASSES` — a frozen map of the assertion classes, each a Chinese regex: `market` (全市场|市场广度|全板块|涨跌家数), `sentiment` (情绪周期|情绪|赚钱效应|亏钱效应|冰点), `theme` (题材|主线|板块轮动|轮动), `leader` (龙头|总龙头|空间板), `index` (指数|大盘|成交额|流动性). `SCOPE_EXEMPT` is stage 0's exemption regex (缺少|…|仅凭).
  - `validateEnvelope(raw, { module, context, schema, owns, rules })` → the parsed artifact, or throws through `fail`. Order: string ≤ 24 KiB → JSON parse (`SCHEMA` on failure) → object ≤ 24 KiB compact → `checkSchema` against the module schema merged with the envelope schema → envelope fields equal the context's (`module`, `snapshot_id`, `run`, `as_of`, `session`, `contract_version`, `hypotheses_version`; mismatch is `"Snapshot or envelope mismatch."`, category REFERENCE) → every evidence id cited anywhere exists in `context.evidenceIds` (`"Unknown evidence reference"`) → the CURRENT/HISTORICAL rule per claim (stage 0's `references` messages: a CURRENT claim cites evidence whose session equals the run's session; HISTORICAL cites only older evidence; INSUFFICIENT forbids every headline field but `UNKNOWN` values) → `FORBIDDEN_TEXT` on every string, except names in `context.labelAllow` (empty in this plan) → scope: a sentence (split on 。；;.!?！？) matching a `SCOPE_CLASSES` class is accepted only if the class is in `owns` and its claim cites at least one id from `context.derivedIds`, or the sentence matches `SCOPE_EXEMPT`; else `"Unsupported whole-market, theme, or leadership assertion."` → `status: "NOT_EVALUABLE"` requires `missing_sources` non-empty and every headline field at its `UNKNOWN`/empty value, and `"OK"` requires `missing_sources` empty and `context.missing` empty → `rules(parsed, context)` (the module's own).
  - Evidence time scope (for the CURRENT/HISTORICAL rule): an item of kind `bars` or `history` is HISTORICAL evidence; every other item is CURRENT evidence when its file's `session` equals the run's `session`, else HISTORICAL. A CURRENT claim cites at least one CURRENT item; a HISTORICAL claim cites only HISTORICAL items and uses no `CURRENT_WORDS`.
  - `buildContext({ module, run, manifest, evidence, sources, derivedFirst, priority, hypotheses, schema, hints, example, required })` → `{ text, digest }`; `evidence` is `[{ source, session, items }]` for every file of the run, and only the files whose source is in `sources` (the module's own list, a superset of `required`) enter the context and the digest: a JSON object `{ module, contract_version, hypotheses_version, run, snapshot_id, as_of, session, status_expected, missing, hypotheses, schema, hints, example, evidence: [...], derived: [...], truncated: [...] }` where `missing` lists required sources absent from the manifest, `status_expected` is `"NOT_EVALUABLE"` when `missing` is non-empty; `derived` items come first, then evidence rows in `priority` order, added whole until the UTF-8 text would pass 30 KiB; every row left out is named in `truncated` as `{source, kind, count}`. `digest` is `{ evidenceIds: Set, derivedIds: Set, missing, snapshot_id, run, as_of, session, hypotheses_version, contract_version, module, labelAllow: [] }` — the validator's `context` argument.
- `contract.mjs` keeps `buildAnalysisContext`, `ANALYSIS_JSON_SCHEMA`, `validateAnalysis`, `buildSchemaExample`, `FACT_CHECK_HINT`, `buildFactChecks` and stage 0's own assertion rule (its single regex), now importing the moved helpers.
