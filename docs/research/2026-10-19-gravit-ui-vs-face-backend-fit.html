gravit-ui 与现有后端的匹配度

这版前端是按 Linqi 的账户服务画的（spec §1.1、§1.5、§9），拿它替换 main 的 face 客户端等于把它反过来挂到 dsh 上。对 dsh 这边：会话、审批卡、群聊三样核心接得上——审批卡比原设计更真；行情和持仓只读能接一半；额度、手动下单、钱包、Memory、插件商店、邮件、电话、推送八块要么没有后端、要么直接撞宪章。

按屏幕

按行计：FIT 算 1、PARTIAL 算 0.5、GAP 和 CONFLICT 算 0；点一块只看那一屏的行。

三个"后端"

face + dsh（主对照）

face/ 进程内托管 dsh 0.2.0-rc.2，127.0.0.1:3090，cookie 登录。

  • Remote：session/*、commands/execute、subagents/*、workspace/*、credentials/describe
  • 三种流：$events（审批、提问）、session/control（投影）、session/follow（事件 + 流式）
  • /data/*：channels、sessions、host、memory、plugins、agents、bots、rooms、account、quotes、symbols（只围栏、不要 cookie）
  • face 自己的客户端 face/client：33 个文件 11,148 行

alpaca_kit MCP

dsh 的 MCP 子进程；浏览器不直接碰。

  • 工具结果以 tool/call / tool/result 事件进会话流——收据、拒绝、K 线、持仓的数据都从这里来
  • 下单 = Gravit 的 place_order，Gate 1（旗标 + 钥匙才注册）+ Gate 2（浏览器的审批卡）
  • /data/account.json 的生产者 face_data.py 原样透传 Alpaca 的 account / positions / orders

demo 账户服务（第二候选）

Linqi 的 buyer-agent-demo @ 0ef5131，4820/4821；posture C，face 和 dsh 没有任何代码调用它。

  • /api/account/*（explore、asset、candles、market、compare、quotes、holdings、statement、receive）、/api/order、/api/say、/api/approve、/api/exchange（EIP-712 签名信封）
  • Markets / Trade / Account 三屏就是从它的页面移植的，连词汇都对得上
  • 默认真钱（real: true，每单/每次转账 100 美元上限）
demo 服务只答自己的页面：server.ts:324-338 的中间件拒绝外来 Host、Origin 和跨站 Sec-Fetch-Site。face 在 3090 端的页面不能从浏览器调 4820。"一个前端两个后端"只有把页挂进 demo 进程（spec §9.1）或 face 侧做代理（demo 的文档明确不要）两条路。

#种类结论对应 · 说明

两条路线

建议 · 路线 A

gravit-ui 做 face 的新客户端

  1. 壳 + Messages + 两张卡（订单、提问）+ 房间——这一期就能替掉现有客户端的大半，审批卡比原设计更真。
  2. Markets + Account 只读：搜索、行情、自选、持仓、订单；新加一条 bars 路由和 bid/ask 两个字段。
  3. Discover 退化成"我的插件"清单 + 频道入口（在哪建会话、落地页）。

按宪章从界面拿掉、不留假门：额度 chip、Beast、Trade 的手动下单与 Cancel（只留 Hand to Gravit）、钱包 / Move / Receive、Mail、电话、早报 / 横幅 / 监控推送、Memory（等 §10.16 那一轮）。补回必须的研究面：频道选择、过程卡的折叠视图、fork / 归档 / 删除、斜杠命令。先写 spec：这步改的是产品边界，不是实现细节。

路线 B

按 spec 原意挂到 demo 的账户服务

  • Markets / Trade / Account 几乎 1:1：持仓键、CAP_USD = --live-cap 默认 100、QUOTE_MS = MONEY_TTL_MS 十分钟、What you sign 的字段就是 liveOrder 的形状；两处不同：mode 在线上叫 guard | open，IBKR 接不了。
  • 要补客户端的 prepare → 签名 → /api/exchange（配对码、P-256 设备钥、nonce 信封）——gravit-ui 现在"按一下就当签了"。
  • Messages 侧 §9.2–§9.6（每任务日志、signed say、商店 MCP 面、Memory、定时推送）在 demo 里同样没有。
  • face 不动，两件产品继续各自是各自；demo 默认真钱。
不可行

一个前端同时接两个后端

  • demo 的围栏不答外来页面（见上）。
  • 真要做就是把 2026-10-05 记录的五个冲突——gate、signer、network、card-per-write、ledger——逐个决定（docs/superpowers/plans/2026-10-05-venue-plugins-unification-handoff.md §12.1）。

顺手发现的 dsh 座席（face 没用过）

都不在 DEVELOPMENT.md 里；用之前再对一遍 face/node_modules/@deepseek-ai/*。

  • session/search：全文检索，{query} → 20 条 {sessionId, snippet}，索引消息文本、工具名和参数、工具结果；是否挂了 ctx.sessionQuery 未证实。
  • dsh-tool-ask-user 的 timed 模式：timeout → wait.timed、宿主算的 remainingMs 流、userQuestions 投影——整棵树里唯一真实的"answer by"；face 跑的是无配置的 legacy 阻塞模式。
  • session/list 的行没有标题字段（在 projections.values.title）、没有未读、没有预览；每条 v4 事件都带 time，mapper 的 FrameView 只留了 seq。
  • 运行时挂 MCP 服务器：dsh-mcp-client 的 apply(ctx, config) 是普通 cordis 插件，可像 declareBots 那样挂为子 fiber；缺一个 face 自己的持久化文件和界面。dsh-plugin-manager、config-editor、hmr 装着但按 D1 不挂。
  • dsh 只是 MCP 客户端：装的是 @modelcontextprotocol/client + core，server 是 devDependency 没装；face 当不了 MCP 服务器。
  • 工具名合约：带点号的原始名（shop.search）会被规范化并加 12 位 SHA-256 后缀。
  • PromptContentPart = text | image{base64} | file{receiptId}；上传走 /api/session/uploadFileBinary 或 fileUploads/upload，收据按 agent 作用域——先有会话才能传文件。
  • workspace/archiveSession / unarchiveSession：归档后不跑模型；face 的 /data/sessions/archive 按 D14 只是展示层。
  • Gate 2 的卡不带参数，但 follow 流里同一 callId 的 tool/call 带 data.arguments；bot 的 allow 表是可见性不是权限——真写进 place_order，Gate 2 照样在成员会话上弹卡。
  • 行情线：每请求 100 个 id、8 个并发、200 个活跃 id、IEX 流 30 个美股；crypto 只有 USD 腿；cn 成交量永远 null；线上没有 bid/ask，但 Alpaca snapshot 和 Coinbase ticker 都带。
