# 数据与决策契约

本文件规定领域服务与 dsh 插件之间的边界。`contracts/*.schema.json` 是待实施的 JSON Schema 2020-12 契约；示例只验证结构和设计一致性，没有连接真实行情或交易系统。Schema 不能取代下文的跨对象和时点校验。

## 1. 数据来源与时间

| 数据 | 必需字段与频率 | 可信边界 |
|---|---|---|
| 证券主数据 | 交易所、板块、上市及退市日、风险警示、停复牌、有效期 | 按历史有效区间查询；不能用今日股票池回测过去 |
| 交易规则 | 生效时间、买卖单位、价格步长、涨跌停价、交易阶段、可卖规则 | 每只证券/交易日从版本化规则与行情共同生成 |
| 行情 | 逐笔或快照时间、接收时间、买卖价量、成交量、累计成交额 | 分钟线仅支持分钟级假设；不推断秒内路径或队列顺序 |
| 公告与新闻 | 原文、发布时点、首次可用时点、采集时点、修订时点、来源链接/哈希 | 公告优先；转述不自动升级为事实，盘后内容不能进入盘中决策 |
| 题材关系 | 证券、题材、关系证据、首次发现时间、有效区间、置信标记 | “市场在炒”与“确有相关业务”分别记；映射不能随今日概念库回填 |
| 账户与订单 | 账户版本、可用/预占资金、总持仓、可卖/冻结数量、回报序号 | 账本和券商回报为事实来源；dsh 会话没有最终解释权 |

每条记录同时保留 `event_time`、`published_at`（适用时）、`available_at`、`ingested_at` 和 `revision_id`。历史回放只有 `available_at <= as_of` 的记录可被读取；`available_at` 是在该数据环境中实际可见的最早时间，不得由公告日期猜出具体小时分钟。

对于现在补采的历史数据，还要区分 `historical_available_at` 与本次 `ingested_at`：只有供应商能够提供可核查的历史分发时点，才允许用前者回放。缺少该证据的数据不纳入严格时点评测，单列探索性结果。修订后的数据另开版本，不能覆盖旧版本。

Evidence schema 显式保留可为空的 `published_at`、`received_at`、`historical_available_at` 和 `availability_proof_ref`。`received_at` 表示原始分发接收时间，`ingested_at` 表示进入当前证据库的时间；补采不能伪造前者。`availability_basis` 区分实时接收、已核实历史分发、合成样本；实时记录须有接收时间，历史记录须有历史可用时间及证明引用，合成样本只能进入合成环境。服务端依据对应来源计算 `available_at`，不得早于该来源可证明的公开及接收时点。

停牌、迟到和缺失值不是零。缺失关键字段时策略返回 `NOT_EVALUABLE`，账户侧禁止新增风险。数据许可和字段可得性未验证前，依赖 L2 封单变化的策略不进入首版。

## 2. 关键领域对象

| 对象 | 关键字段 | 唯一性与生命周期 |
|---|---|---|
| `Evidence` | `evidence_id, kind, source_ref, event_time, available_at, content_hash, payload` | 不可变；纠错产生新 revision |
| `DecisionSnapshot` | `snapshot_id, as_of, universe_version, market_rules_version, data_quality, evidence` | 同一决策内的共同数据截面；所有快照内容纳入哈希 |
| `MarketState` | 环境、情绪、题材、个股四层状态、冲突、证据 | 记录在线版本；事后标签另表存储 |
| `ExpectationPlan` | `plan_id, frozen_at, revision, valid_window, scenarios, invalidate_if` | 冻结后只追加修订；每次触发需指定计划版本 |
| `Decision` | `decision_id, snapshot_id, task_revision, plan_revision, plan_hash, exit_policy_version, exit_policy_hash, action, claims, counterevidence, intent` | 绑定不可变计划和退出规则；工具写入后成为结构化记录，不靠聊天文本解析 |
| `RiskDecision` | `decision_id, intent_id, policy_version, account_version, verdict, reasons, permit` | ALLOW 也有失效时间；不代表已下单 |
| `Order` / `Fill` | 业务幂等键、券商 ID、累计数量、成交 ID、事件时间和接收时间 | 成交按唯一 ID 去重；订单状态通过回报和查询确认 |
| `Experiment` | 数据/模型/提示词/策略/成本/撮合版本、训练测试区间、完整运行集合 | 失败实验也保留，禁止只留下最好一次 |

## 3. 特征计算与假设的边界

初版用可审计的确定性函数计算基础特征。LLM 可以解释因果假设与冲突，不能改写特征值。

- **连板高度**：基于当日适用涨停价与截至当前时点的状态；昨日收盘连板高度与今日盘中触板高度分开。盘中看过涨停但已炸板，不可记为已确认连板。
- **昨日强势组合表现**：昨日收盘前冻结入选规则，今日计算可交易股票的收益分布和负尾部比例；同时报告不可交易和缺失数，不能静默剔除跌停或停牌。
- **炸板与封板比例**：按唯一股票数计算截至当前时点触板后回落/仍封板的比例；另记重复开板次数，不能混用分母。
- **题材广度**：基于当时已知成分的上涨、触板、封板、成交额占比；新加入成员自其可用时间起计入，不回写全天。
- **量能变化**：累计成交额与过去可用交易日“同一交易时刻”的中位数比较；不能拿上午成交额直接除全天阈值。
- **相对强弱**：个股收益相对冻结题材篮子和市场基准；用于候选排序，不等价于领涨因果。
- **分歧修复**：预先定义回撤、企稳、重回参考价和题材改善的联合条件，输出是否满足及未满足条件，避免“上涨就是修复”的循环定义。

所有公式版本化。阈值和权重只用训练区间确定；未知情绪指数定义的原文数值先保留为研究线索，不转换成伪精确因子。

## 4. 预期差如何成为可回放对象

盘前计划至少包含三个条件分支：符合预期、强于预期、弱于预期。每个分支规定观察窗口、可测量指标及动作候选，例如“在开盘后确认窗口内，核心相对强弱保持为正且题材广度恢复”。具体阈值由对应策略版本提供，不在自然语言中临时改变。

预期差是观测值对**之前冻结的区间或条件**的偏离，不能使用模型看到结果以后重新写出的“原本预期”。定性催化用证据等级与尚未确认事件表示；缺乏可靠样本时不强行给出精确概率。

对持仓，退出条件在入场前登记，包括逻辑失效、最大持有窗口、风险预算触发和数据失效处理。T+1 下触发退出但无可卖数量时，记录 `EXIT_BLOCKED` 及下一次可执行条件，禁止把期望的止损价写成成交价。

## 5. dsh 工具表面

下列名称是本项目拟定义的工具，不是 DeepSeek 自带交易 API。工具由已核实的 dsh 工具注册接口接入，详见 [dsh 接入设计](dsh-integration.md)。

| 工具 | 参数摘要 | 返回 | 副作用 |
|---|---|---|---|
| `market_snapshot_get` | `snapshot_id` | 固定时点特征、规则引用、质量状态 | 无 |
| `evidence_get` | `snapshot_id, evidence_ids` | 截至快照可见的证据与原文引用 | 无；禁止越过 as_of |
| `playbook_get` | `strategy_id, version` | 适用条件、否决条件、参数、来源 | 无 |
| `account_summary_get` | 匿名账户引用、版本 | 风险暴露、可卖数量、预占摘要 | 无；不返回账户密钥 |
| `decision_submit` | 完整 `Decision` | 接收 ID 或字段错误 | 只写交易意图库，不下单 |
| `review_record` | 决策 ID、归因、证据、实验建议 | 复盘工件 ID | 只写研究记录 |

`snapshot_id` 授权范围由服务端绑定，模型不能在参数里改 `as_of` 获得未来数据。按需分页、固定候选集合和字段白名单限制上下文膨胀。行情与公告内的文字是数据，不是对 agent 的指令。

## 6. 提交与风控的事务边界

1. `decision_submit` 检验 schema、快照和策略版本、证据引用、计划冻结时间、提案有效期。将通过验证的意图和 outbox 事件在一个数据库事务内写入；重复幂等键返回已有结果。
2. 风控消费意图，在同一账户锁/可串行化事务内重读余额、已有持仓和未结订单，计算最终允许数量，预占最坏限价金额与费用，写 `RiskDecision` 和订单发送任务。风控可缩量或拒绝，不能把 BUY 改成别的研究标的。
3. 网关仅接受由风控服务签发并能在服务器核验的短期许可。许可绑定账户、完整决策与意图内容哈希、快照、任务修订、证券、方向、价格约束、最大数量、账户版本、风险配置、到期时间和唯一 nonce；JSON 里出现 `ALLOW` 字样本身不构成授权。计划与退出规则哈希由可信领域服务计算并验证，不相信模型自行填入的哈希。
4. 网关发送前检查交易时段、当前报价/涨跌停价、有效期、资金预占和可卖数量。许可一次性消费；取消和重试走状态机。没有券商幂等语义时不能承诺 exactly-once，只能通过唯一意图、查询、预占和对账处理不确定结果。
5. 订单确认、部分成交、撤单和资金释放都以可去重事件落入同一账本；每个读模型标记最后确认版本。外部副作用不依赖 dsh 会话是否写入成功。

原子预占只能解决系统内部并发；账户若允许外部手工交易，必须实时对账，账户版本漂移时原许可失效。实盘阶段应优先使用专用账户以缩小这种竞争。

## 7. Schema 之外的必验不变量

- `snapshot.as_of <= decision.as_of < valid_until`；所有依赖证据的 `available_at <= snapshot.as_of`。
- 冻结计划时间不得晚于被评价的观测起点；`snapshot_id`、策略版本和证据集合必须真实存在且匹配。
- `plan_id + plan_revision + plan_hash` 和 `exit_policy_id + exit_policy_version + exit_policy_hash` 必须解析到唯一不可变内容。任务协调器维护单调 `task_revision`，新计划、失效公告或状态反转可使旧修订失效；提交和发送前都检查当前修订，迟到结果不得恢复旧信号。
- 信号快照有独立于意图 TTL 的最大年龄。盘口刷新不能刷新旧论点的年龄；超过策略允许窗口必须重新研究。费用与报价、信号、账户版本都要分别检查，不能用“刚收到报价”代替全部时效检查。
- WAIT / WATCH 的 `intent` 必须是 null；PROPOSE 仅 BUY；REDUCE / EXIT 仅 SELL；这些结构约束由 schema 覆盖。
- 最终数量为正、符合当日交易单位；BUY 的最低价不高于最高价；SELL 数量不超过可卖数量减去冻结数量。
- 风险裁决 `REJECT / DEFERRED` 不能含许可；`ALLOW` 必须含预占记录和绑定完整意图的许可。订单 `EXPIRED` 与风险裁决是不同状态，过期许可不可继续使用。
- 风控许可的证券/方向必须与原意图相同，数量不得超过原提案，价格区间必须是原区间的子集；许可到期不得晚于意图到期。BUY 预占现金须覆盖允许数量按最坏限价的金额和费用，SELL 冻结数量须至少覆盖允许数量；schema 只校验正数，金额和区间包含关系由领域服务验证。
- `filled_qty + canceled_qty + remaining_qty = original_qty`（已确认状态下）；重复成交不得重复记账，未知状态不得释放资金。
- 模型自报确信度、子 agent 投票和用户在聊天里输入的金额都不能覆盖系统风险配置。

## 8. 合成例子

[synthetic-repair.json](../examples/synthetic-repair.json) 是“主线分歧修复，但主张还需通过确定性策略门槛和风控”的合成示例。`SYNTHETIC-01` 不是真实证券，例子不构成股票推荐。

该例用冻结计划、行情及题材证据生成 BUY 提案，再给出“资料不足，DEFERRED”的风险响应。这样可以验证：一个叙事合理、schema 正确的提案，仍不能在账户或市场规则快照缺失时变成订单。

[synthetic-wait.json](../examples/synthetic-wait.json) 展示观察信息缺失时的 WAIT。实施阶段要另提供正常 ALLOW 后部分成交、取消竞态、UNKNOWN 恢复的端到端场景，而不能只验证成功路径。
